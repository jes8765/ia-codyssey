# 프로젝트 2. 자유 주제 자동화 설계 및 구현

## 1. 프로젝트 개요

### 1.1 프로젝트 주제

본 프로젝트에서는 **Unity 게임 프로젝트 GitHub 변경사항 자동 알림 시스템**을 구현하였다.

게임 개발 과정에서 GitHub 저장소에 코드나 리소스가 업데이트될 때마다 팀원들이 직접 저장소를 확인해야 하는 불편함이 존재한다.

이를 해결하기 위해 GitHub Push 이벤트를 감지하여 변경사항을 자동으로 Discord 채널에 공유하고 Google Sheets에 기록하는 자동화 시스템을 구축하였다.

---

## 2. 자동화 대상 업무 정의

### 2.1 기존 업무 방식

Unity 프로젝트를 팀 단위로 개발할 경우 다음과 같은 반복 업무가 발생한다.

1. GitHub 저장소에 코드 또는 에셋을 업로드한다.
2. 팀원들이 직접 GitHub를 확인한다.
3. 변경 내용을 Discord 채널에 공유한다.
4. 작업 내역을 별도로 기록한다.

위 과정은 프로젝트 규모가 커질수록 반복 횟수가 증가하며 누락 가능성이 존재한다.

---

### 2.2 자동화 목표

GitHub 저장소에 새로운 Push가 발생하면 자동으로 변경사항을 감지하고 Discord 채널에 알림을 전송하며 Google Sheets에 작업 내역을 기록하는 것을 목표로 한다.

---

## 3. 자동화 도구 선정

### 3.1 선정 도구

**Make**

---

### 3.2 선정 이유

1. GitHub 연동을 기본 제공한다.
2. Router를 이용한 조건 분기 구현이 쉽다.
3. Discord 연동이 가능하다.
4. Google Sheets 연동이 가능하다.
5. 시각적인 워크플로우 구성으로 흐름을 확인하기 쉽다.
6. 무료 플랜만으로 과제를 수행할 수 있다.

---

## 4. 워크플로우 설계

### 4.1 전체 흐름

1. GitHub 저장소에 Push가 발생한다.
2. Make가 Push 이벤트를 감지한다.
3. Push된 브랜치를 확인한다.
4. 브랜치에 따라 분기 처리한다.
5. Discord 채널에 변경사항을 전송한다.
6. Google Sheets에 작업 이력을 기록한다.

---

### 4.2 워크플로우 다이어그램

```text
GitHub Push
      ↓
브랜치 확인
      ↓
 ┌─────────────┬─────────────┐
 │             │             │
main 브랜치   develop 브랜치
 │             │
 ↓             ↓
Discord      Discord
알림         알림
 │             │
 ↓             ↓
Google       Google
Sheets       Sheets
기록          기록
```

## 7. 자동화 효과

1. GitHub 변경사항을 실시간으로 공유할 수 있다.
2. 팀원들이 저장소를 직접 확인할 필요가 없다.
3. 작업 내역을 자동으로 기록할 수 있다.
4. 프로젝트 진행 상황을 쉽게 추적할 수 있다.
5. 반복적인 보고 업무를 줄일 수 있다.

---

## 8. 최종 의견

본 프로젝트를 통해 GitHub, Discord, Google Sheets를 연동하여 실제 개발 환경에서 활용 가능한 자동화 시스템을 구현할 수 있었다.

특히 GitHub Push 이벤트를 기반으로 변경사항을 자동으로 공유하고 기록하는 과정을 통해 Trigger, Action, Router의 개념을 실제 업무 흐름에 적용해 볼 수 있었다.

향후에는 생성형 AI를 연동하여 Commit Message를 자동 요약하거나 변경 내용을 분석하는 기능까지 확장할 수 있을 것으로 기대된다.
