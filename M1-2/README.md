# StockMate (NVDA AI Assistant) --- 최종 과제 보고서

엔비디아(NVDA) 시계열 주가 데이터를 요약하고, 요약 정보를 OpenAI 시스템
프롬프트에 주입해 데이터 기반 답변을 제공하는 AI 웹 서비스입니다.

> **프로젝트 핵심:** Firestore에 저장된 데이터를 백엔드에서 분석하고, 그
> 결과를 AI에 전달하여 일반적인 답변이 아닌 서비스 데이터에 기반한
> 대화를 제공하는 것입니다.

## 1. 프로젝트 개요

### 1.1 프로젝트 목적

일반적인 생성형 AI는 사용자의 데이터베이스에 저장된 개인 데이터를
자동으로 알지 못합니다. 예를 들어 "현재 내 주가 데이터는 어떤
상황인가?"라고 질문해도, 해당 데이터가 제공되지 않으면 일반적인 주식
지식에 기반한 답변만 생성할 수 있습니다.

StockMate는 FastAPI, Firebase Firestore, OpenAI API를 연동해 사용자의
시계열 데이터를 저장·분석하고, 요약 정보를 AI 대화의 컨텍스트로 전달하는
**개인화 데이터 분석 비서**를 구현하는 프로젝트입니다.

주요 목표는 다음과 같습니다.

-   NVDA 주가 데이터 저장 및 관리
-   데이터 요약 통계 제공
-   요약 정보를 활용한 AI 채팅
-   대화 기록 저장, 조회, 불러오기 및 삭제
-   웹 프론트엔드와 백엔드 배포

### 1.2 데이터 선정

분석 대상으로 엔비디아(NVDA)의 주가 데이터를 선택했습니다. 프로젝트에는
**1,254개 데이터 레코드**를 사용했습니다. 실제 데이터 기간과 각 통계값은
데이터베이스의 현재 상태를 기준으로 확인해야 합니다.

### 1.3 기술 스택

  -----------------------------------------------------------------------
  기술                                사용 목적
  ----------------------------------- -----------------------------------
  Python                              백엔드 개발 언어

  FastAPI                             API 서버 및 엔드포인트 구성

  Pydantic                            요청 데이터 구조 및 타입 검증

  Firebase Admin SDK / Firestore      주가 데이터와 대화 기록 저장

  OpenAI API (`gpt-4o-mini`, 실제     데이터 요약을 참고한 AI 답변 생성
  설정 기준)                          

  HTML / CSS / Vanilla JavaScript     프레임워크 없이 구현한 웹
                                      프론트엔드

  Render                              백엔드 배포

  Vercel                              프론트엔드 배포
  -----------------------------------------------------------------------

## 2. 기술 스택을 선택한 이유

### FastAPI

FastAPI를 이용하면 Python으로 HTTP API를 구성하고, Pydantic 모델을
이용해 요청 데이터를 검증할 수 있습니다. 라우터와 서비스 코드를 분리해
데이터 관리와 AI 호출을 구분할 수 있습니다.

### Firebase Firestore

Firestore는 컬렉션과 문서 단위로 데이터를 저장하는 NoSQL
데이터베이스입니다. 날짜별 주가 레코드와 대화 기록을 문서 단위로 관리할
수 있습니다.

### OpenAI API

백엔드가 생성한 데이터 요약을 시스템 프롬프트에 전달해, GPT가 저장된
데이터에 기반한 답변을 생성하도록 구성합니다. 컨텍스트를 제공하면 데이터
기반 답변을 유도할 수 있지만, 답변의 정확성이 자동으로 보장되는 것은
아닙니다.

### Vanilla JavaScript

HTML, CSS, JavaScript만 사용해 화면을 구성했습니다. 별도의 프론트엔드
프레임워크 없이 탭 전환, 데이터 목록 갱신, 채팅 메시지 표시와 같은 UI
동작을 구현합니다.

## 3. 시스템 아키텍처 및 데이터 흐름

### 3.1 전체 구조

``` text
[사용자]
   |
   v
[Vercel 프론트엔드]
HTML / CSS / Vanilla JavaScript
   |
   | HTTP 요청
   v
[Render 백엔드]
FastAPI
   |
   +--> routers/ : 요청 및 응답 처리
   |
   +--> services/ : 데이터 처리, 통계 요약, AI 호출
   |       |
   |       +--> Firestore : 주가 데이터 / 대화 기록
   |       |
   |       +--> OpenAI API : 컨텍스트 기반 답변 생성
   |
   v
[JSON 응답 반환 및 화면 갱신]
```

### 3.2 AI 채팅 데이터 흐름

1.  사용자가 프론트엔드에서 질문을 입력합니다.
2.  프론트엔드가 `POST /api/chat`으로 질문을 보냅니다.
3.  백엔드 서비스가 Firestore에 저장된 주가 데이터를 기반으로 요약
    정보를 가져옵니다.
4.  요약 정보를 시스템 프롬프트에 포함해 OpenAI API를 호출합니다.
5.  AI가 생성한 답변을 사용자에게 반환하고, 대화 내용을 Firestore에
    저장합니다.
6.  프론트엔드는 답변과 로딩 상태를 화면에 반영합니다.

## 4. 주요 기능 및 API

### 4.1 데이터 관리

  기능               메서드   엔드포인트
  ------------------ -------- ---------------------
  데이터 추가        POST     `/api/data`
  데이터 목록 조회   GET      `/api/data`
  데이터 수정        PUT      `/api/data/{id}`
  데이터 삭제        DELETE   `/api/data/{id}`
  데이터 요약 조회   GET      `/api/data/summary`

데이터 레코드는 과제에서 요구한 `date`, `value`, `memo` 형태를 기본으로
합니다. 프론트엔드에서 작업한 뒤 목록을 갱신하고, 변경 결과가
Firestore에 반영되는지 확인합니다.

### 4.2 AI 채팅 및 대화 기록

  ---------------------------------------------------------------------------
  기능                    메서드                  엔드포인트
  ----------------------- ----------------------- ---------------------------
  AI 질문 및 대화 자동    POST                    `/api/chat`
  저장                                            

  대화 목록 조회          GET                     `/api/conversations`

  대화 기록 삭제          DELETE                  `/api/conversations/{id}`

  특정 대화 불러오기      GET                     `/api/conversations/{id}`
                                                  또는 목록 응답에 메시지
                                                  포함
  ---------------------------------------------------------------------------

> **구현 확인:** 위 표의 대화 삭제 및 특정 대화 불러오기 엔드포인트는
> 실제 백엔드 코드와 일치하는지 확인해야 합니다. 삭제 버튼이 화면에
> 있거나 대화 목록이 보이는 것만으로 해당 API 요구사항이 충족되는 것은
> 아닙니다. 특정 대화 조회 API가 없다면 `GET /api/conversations`가
> 메시지 전체를 반환하는지 확인하고, 그렇지 않으면 불러오기 요구사항을
> 보완해야 합니다.

### 4.3 데이터 요약

요약 API는 AI가 참고할 수 있는 통계 정보를 제공합니다. 현재 코드가
실제로 계산하는 항목만 결과로 설명해야 합니다.

  -----------------------------------------------------------------------
  항목                                설명
  ----------------------------------- -----------------------------------
  기간                                데이터의 가장 이른 날짜부터 가장
                                      최근 날짜까지

  개수                                저장된 데이터 레코드 수

  평균                                종가 데이터의 산술평균

  최대 / 최소                         종가 데이터의 최고값과 최저값

  최근 추세                           최근 구간과 이전 구간을 비교하는 등

> **주의:** 평균·최대·최소만으로 최근 추세를 알 수는 없습니다. 코드에서

## 7. 로컬 실행 방법

### 7.1 백엔드 실행

프로젝트 루트가 `M1-2`인 경우 다음 명령어를 실행합니다.

``` bash
cd backend
python -m venv .venv
```

macOS / Linux:

``` bash
source .venv/bin/activate
```

Windows:

``` powershell
.venv\Scripts\activate
```

패키지 설치 및 서버 실행:

``` bash
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

서버가 실행되면 다음 주소를 확인합니다.

-   API 기본 주소: `http://localhost:8000`
-   Swagger UI: `http://localhost:8000/docs`

### 7.2 프론트엔드 실행

새 터미널에서 프로젝트 루트 기준으로 실행합니다.

``` bash
cd frontend
python -m http.server 3000
```

브라우저에서 `http://localhost:3000`에 접속합니다.

> 프론트엔드의 API 기본 주소가 로컬 백엔드 또는 배포 백엔드 중 어느 쪽을
> 가리키는지 확인해야 합니다. 로컬 테스트 시에는 보통
> `http://localhost:8000`을 사용합니다.

## 8. 환경변수 및 보안

백엔드 실행에 필요한 환경변수는 `backend/.env`에 설정합니다. 실제 키를
저장소에 커밋하지 말고, `.env.example`에는 변수명과 설명만 기재합니다.

  --------------------------------------------------------------------------------------
  변수                              용도                    값 예시
  --------------------------------- ----------------------- ----------------------------
  `OPENAI_API_KEY`                  OpenAI API 인증         `your_openai_api_key_here`

  `FIREBASE_SERVICE_ACCOUNT_JSON`   Firebase 인증 JSON      실제 인증 정보는 공개하지
                                    문자열 또는 코드에서    않음
                                    지원하는 키 파일 경로   

  `ALLOWED_ORIGINS`                 CORS 허용 출처 목록     로컬 주소와 실제 Vercel
                                                            도메인

  `API_BASE_URL`                    프론트엔드에서 사용할   실제 Render URL
                                    백엔드 주소             
  --------------------------------------------------------------------------------------

보안 유의사항:

-   `.env`, Firebase 서비스 계정 JSON, API 키를 GitHub에 업로드하지
    않습니다.
-   `.gitignore`에 비밀 파일을 추가합니다.
-   비밀키는 Render 등 백엔드 실행 환경의 환경변수로 설정합니다.
-   브라우저에서 실행되는 JavaScript에 OpenAI API 키나 Firebase 관리자
    키를 넣지 않습니다.
-   CORS는 가능한 한 실제 프론트엔드 도메인과 필요한 로컬 개발 주소만
    허용합니다.
-   `FIREBASE_SERVICE_ACCOUNT_JSON`에 JSON 문자열을 넣는 방식과 파일
    경로를 넣는 방식은 서로 다릅니다. `backend/firebase/client.py`가
    지원하는 방식에 맞춰 README와 배포 환경을 설정해야 합니다.

예시 `.env.example`:

``` dotenv
OPENAI_API_KEY=your_openai_api_key_here
FIREBASE_SERVICE_ACCOUNT_JSON=path_to_firebase_key.json
ALLOWED_ORIGINS=http://localhost:3000,https://your-frontend.vercel.app
```

> 위 `FIREBASE_SERVICE_ACCOUNT_JSON` 예시는 코드가 파일 경로 방식을
> 지원할 때만 사용합니다. JSON 문자열 방식으로 구현했다면 해당
> 환경변수에 JSON 문자열을 등록하는 방식으로 안내를 바꿔야 합니다. 실제
> 비밀키는 `.env.example`에 넣지 않습니다.

## 10. 기술 개념 및 구현 원리

### 10.1 시계열 데이터 분석 및 요약

시계열 데이터(Time Series Data)는 시간 순서에 따라 기록된 데이터입니다.
StockMate는 날짜별 NVDA 주가 데이터를 사용합니다.

처리 흐름은 다음과 같습니다.

1.  Firestore의 `data` 컬렉션에서 데이터를 조회합니다.
2.  날짜를 기준으로 정렬합니다.
3.  데이터 개수, 평균, 최고값, 최저값 등을 계산합니다.
4.  실제 구현되어 있다면 최근 데이터와 이전 데이터를 비교해 추세를
    산출합니다.
5.  요약 정보를 화면에 표시하고 AI 프롬프트에 전달합니다.

요약 정보는 주요 통계를 빠르게 파악하게 해 주며, 모든 원본 데이터를 매번
프롬프트에 넣는 것보다 입력 길이를 줄이는 데 도움이 됩니다. 다만
평균·최대·최소만으로는 추세를 판단할 수 없으므로 추세는 별도의 비교
계산이 필요합니다.

### 10.2 FastAPI 라우터와 서비스 분리

  구성 요소     역할
  ------------- -------------------------------------------
  `main.py`     FastAPI 앱 초기화, CORS 설정, 라우터 등록
  `routers/`    HTTP 엔드포인트 및 요청·응답 처리
  `services/`   데이터 조회·분석, AI 호출, 대화 저장
  `firebase/`   Firestore 연결과 인증
  `schemas/`    요청 데이터의 구조와 검증 규칙 정의

예를 들어 데이터 조회는 다음과 같은 흐름으로 처리됩니다.

`사용자 요청 → routers/data.py → services/data_service.py → Firestore → 응답`

기능을 분리하면 API 처리와 비즈니스 로직, 데이터베이스 접근이 한 파일에
뒤섞이지 않아 유지보수와 테스트가 쉬워집니다.

### 10.3 Pydantic을 이용한 요청 검증

Pydantic 모델은 API 요청 데이터의 타입과 구조를 정의합니다.

``` python
from pydantic import BaseModel

class ChatRequest(BaseModel):
    message: str
```

위 모델은 `message` 필드가 문자열이어야 한다는 조건을 나타냅니다.
FastAPI는 요청 데이터를 모델에 맞춰 검증하며, 필수 필드가 없거나 타입이
맞지 않으면 일반적으로 `422 Unprocessable Entity`를 반환합니다.

데이터 생성 요청에서는 날짜, 숫자 값, 메모 등의 형식을 검증할 수
있습니다. 단순 타입 검증을 넘어 음수 값이나 지나치게 긴 메모를 막으려면
추가 제약 조건도 정의해야 합니다.

### 10.4 Firestore와 CRUD

Firestore는 컬렉션과 문서 단위로 데이터를 저장하는 NoSQL
데이터베이스입니다. StockMate에서는 `data` 컬렉션에 주가 데이터를,
`conversations` 컬렉션에 대화 기록을 저장합니다.

  CRUD     의미   HTTP 메서드
  -------- ------ -------------
  Create   생성   POST
  Read     조회   GET
  Update   수정   PUT
  Delete   삭제   DELETE

프론트엔드는 문서 ID를 포함해 API 요청을 보내고, 백엔드는 해당 문서를
생성·조회·수정·삭제합니다. 작업이 성공하면 프론트엔드가 목록을 갱신해
사용자에게 결과를 보여줍니다.

### 10.5 컨텍스트 주입(Context Injection)

컨텍스트 주입은 AI가 답변을 생성하기 전에 필요한 정보를 프롬프트에 함께
제공하는 방식입니다.

1.  사용자가 자연어 질문을 입력합니다.
2.  백엔드가 데이터 요약을 조회합니다.
3.  요약 정보를 시스템 프롬프트에 포함합니다.
4.  사용자 질문과 함께 OpenAI API에 전달합니다.
5.  AI가 제공된 정보를 참고해 답변합니다.
6.  대화 내용은 구현된 저장 흐름에 따라 Firestore에 기록됩니다.

시스템 프롬프트 예시:

``` text
당신은 데이터 분석 비서입니다.

[사용자 데이터 요약]
- 데이터 기간: {period}
- 데이터 개수: {count}
- 주요 통계: {metrics}
- 최근 추세: {trend}

제공된 데이터를 근거로 질문에 답변하세요.
확인할 수 없는 정보는 추측하지 말고, 데이터로 확인할 수 없다고 알려주세요.
```

이 방식은 AI가 사용자의 실제 데이터에 기반한 답변을 생성하도록
유도합니다. 다만 AI가 제공된 요약을 잘못 해석할 수 있고, 요약에 포함되지
않은 세부 데이터는 알지 못할 수 있으므로 정확성이 보장되는 것은
아닙니다. 특정 날짜의 값을 물을 때는 해당 데이터를 별도로 조회해
제공하는 방식이 적절합니다.

### 10.6 CORS, 환경변수, 비밀키 관리

프론트엔드와 백엔드는 서로 다른 도메인에서 실행될 수 있습니다.
CORS(Cross-Origin Resource Sharing)는 브라우저가 다른 출처의 서버 응답을
사용할 수 있도록 서버가 허용 출처를 설정하는 정책입니다.

환경변수는 API 키, 인증 정보, 서버 주소처럼 실행 환경마다 달라지는 값을
코드와 분리해 관리하는 데 사용합니다.

-   `OPENAI_API_KEY`: OpenAI API 인증
-   `FIREBASE_SERVICE_ACCOUNT_JSON`: Firebase 인증 정보 또는 코드에서
    지원하는 인증 파일 경로
-   `ALLOWED_ORIGINS`: 백엔드에서 허용할 출처
-   `API_BASE_URL`: 프론트엔드가 요청할 백엔드 주소

API 키와 Firebase 서비스 계정 키가 공개되면 무단 API 사용, 과금, 데이터
접근 문제가 발생할 수 있습니다. 따라서 비밀키는 코드나 프론트엔드에 넣지
않고, GitHub에 커밋하지 않으며, 배포 플랫폼의 환경변수 등 안전한 설정
방식으로 관리해야 합니다.

## 11. 한계점 및 개선 방향

-   **세부 데이터 질의:** 요약에 포함되지 않은 특정 날짜의 주가는 추가
    조회를 통해 제공할 필요가 있습니다.
-   **답변 검증:** AI 답변이 실제 데이터와 일치하는지 테스트하는 절차가
    필요합니다.
-   **추세 분석 개선:** 단순 통계 외에 최근 구간과 이전 구간의 변화율 등
    명확한 계산 기준을 적용할 수 있습니다.
-   **데이터 시각화:** 주가 그래프와 기간별 비교 기능을 추가할 수
    있습니다.
-   **데이터 내보내기:** CSV 또는 JSON 다운로드 기능을 제공할 수
    있습니다.

## 결론

StockMate는 시계열 데이터를 저장하고 요약한 뒤, 그 정보를 AI 시스템
프롬프트에 주입해 데이터 기반의 대화를 제공하는 웹 서비스입니다.
FastAPI, Firestore, OpenAI API, Vanilla JavaScript를 연결하여 데이터
관리와 AI 응답, 대화 기록 관리가 하나의 서비스에서 이루어지도록
구성했습니다.

이 프로젝트를 통해 시계열 데이터 요약, API 계층 분리, 요청 데이터 검증,
Firestore CRUD, 컨텍스트 주입, 배포 환경의 CORS와 비밀키 관리가 실제
서비스에서 어떻게 연결되는지 학습할 수 있습니다.
