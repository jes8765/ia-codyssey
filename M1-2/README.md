# 📊 StockMate (NVDA AI Assistant) - 최종 과제 보고서

> **엔비디아(NVDA) 시계열 주가 데이터를 기반으로 통계적 요약 정보를 산출하고, 이를 OpenAI 시스템 프롬프트에 동적으로 컨텍스트 주입하여 개인화된 맞춤형 답변을 제공하는 Full-Stack AI 웹 서비스**

---

# 1. 프로젝트 개요

## 1.1 프로젝트 목적
일반적인 생성형 AI 서비스(ChatGPT 등)는 사용자가 보유한 구체적인 비즈니스 데이터나 개인화된 시계열 기록(예: 주가, 가계부 등)을 사전에 인지하지 못합니다. "현재 내 주가 상황이나 데이터 통계가 어때?"라고 물어도 일반적인 답변만 돌아오는 한계가 있습니다.

본 프로젝트는 이러한 한계를 극복하기 위해 **FastAPI 백엔드**, **Firebase Firestore**, 그리고 **OpenAI API**를 연동하여 사용자의 실제 시계열 데이터를 백그라운드에서 분석·요약하고, 이를 AI 대화의 컨텍스트로 실시간 주입하는 **'내 상황을 아는 AI 비서'**를 구축하는 것을 목표로 합니다.

또한 단순한 AI 대화에 그치지 않고 데이터 관리(CRUD), 요약 통계 산출, 대화 기록 저장 및 불러오기(History) 기능을 모두 포함한 완성도 있는 싱글 페이지 애플리케이션(SPA) 웹 서비스를 구현하고자 하였습니다.

---

## 1.2 프로젝트 배경
생성형 AI와 자동화 기술이 발전함에 따라 다양한 데이터 분석 도구가 등장하고 있지만, 개인이 보유한 시계열 데이터를 직접 AI와 연동하여 대화형으로 분석하는 서비스는 여전히 구현이 까다롭습니다. 

주가 데이터 분석 업무는 다음과 같은 한계와 요구사항을 지닙니다.
- 방대한 시계열 데이터(1,000건 이상)를 효율적으로 저장하고 관리해야 함
- AI가 사용자의 특정 데이터를 인지할 수 있도록 컨텍스트 주입 메커니즘이 필요함
- 사용자가 언제든지 데이터를 추가, 수정, 삭제할 수 있는 직관적인 CRUD 인터페이스 제공
- 과거 대화 내역을 보존하고 다시 확인할 수 있는 세션 관리 기능 필요

본 프로젝트에서는 **FastAPI + Firestore + OpenAI + Vanilla JS(SPA)** 구조를 설계하여, 사용자가 별도의 복잡한 설정 없이도 자신의 주가 데이터를 관리하고 AI를 통해 정밀한 분석을 받을 수 있는 환경을 구현하였습니다.

---

## 1.3 사용 기술

본 프로젝트에서 사용한 기술 스택은 다음과 같습니다.

| 기술 | 사용 목적 |
|------|-----------|
| **Python / FastAPI** | 고성능 백엔드 API 서버 구축 및 비동기 처리 |
| **Pydantic v2** | 엄격한 요청/응답 데이터 모델 검증 및 직렬화 |
| **Firebase Admin SDK / Firestore** | NoSQL 기반 시계열 주가 데이터 및 대화 기록 영구 저장 |
| **OpenAI API (`gpt-4o-mini`)** | 데이터 요약 컨텍스트가 주입된 맞춤형 AI 응답 생성 |
| **Vanilla HTML5 / CSS3 / JS** | 외부 프레임워크 없는 모던한 SPA 인터페이스 및 동적 DOM 제어 |
| **Render / Vercel** | 백엔드 및 프론트엔드 클라우드 배포 |

각 기술을 선택한 이유는 다음과 같습니다.

### FastAPI
FastAPI는 빠른 속도와 Pydantic을 이용한 자동 데이터 검증 기능 덕분에 AI 연동 백엔드를 구축하기에 매우 적합합니다. 비동기 처리를 지원하므로 대용량 데이터 조회 및 외부 OpenAI API 호출 시 병목 현상을 최소화할 수 있습니다.

### Firebase Firestore
NoSQL 기반의 Firestore는 문서(Document) 단위로 유연하게 데이터를 저장할 수 있어 시계열 주가 데이터와 구조화된 대화 세션 로그를 관리하는 데 최적화되어 있습니다. 서버리스 환경에서 쉽게 연동할 수 있는 장점이 있습니다.

### OpenAI API
`gpt-4o-mini` 모델은 뛰어난 자연어 이해 능력을 제공하면서도 비용 효율적입니다. 시스템 프롬프트(System Prompt)를 통해 실시간 연산된 주가 통계 요약을 주입함으로써 환각 현상을 줄이고 정확한 데이터 기반 답변을 유도할 수 있습니다.

### Vanilla JavaScript (SPA)
추가적인 프레임워크 설정 없이 브라우저 환경에서 가볍고 빠르게 동작하는 싱글 페이지 애플리케이션(SPA) 구조를 구현하여, 화면 깜빡임 없는 매끄러운 탭 전환과 직관적인 UI/UX를 제공합니다.

# 2. 시스템 구성

## 2.1 전체 워크플로우
본 프로젝트에서 구현한 전체 데이터 흐름 및 아키텍처는 다음과 같습니다.

```text
[Frontend (SPA)]
      │
      ├─ GET /api/data/summary ────────► [FastAPI Backend] ──(Firestore)──► 통계 요약 산출
      ├─ GET/POST/PUT/DEL /api/data ───► [FastAPI Backend] ──(Firestore)──► CRUD 처리
      ├─ POST /api/chat ───────────────► [FastAPI Backend] ──(OpenAI)────► 컨텍스트 주입 답변 생성 및 저장
      └─ GET /api/conversations ───────► [FastAPI Backend] ──(Firestore)──► 대화 기록 조회
```

---

## 2.2 핵심 모듈 및 API 설명

### Data API 및 Summary API
* **CRUD (`/api/data`)**: 1,254개의 NVDA 주가 데이터 포인트를 조회, 추가, 수정, 삭제할 수 있는 엔드포인트입니다.
* **Summary (`/api/data/summary`)**: 전체 데이터의 총 레코드 수, 평균가, 최고가, 최저가를 실시간으로 연산하여 반환합니다.

### Chat & Conversation API
* **Chat (`/api/chat`)**: 사용자의 질문을 받아 백그라운드에서 데이터 요약본을 결합한 시스템 프롬프트를 생성하고, OpenAI API를 호출한 뒤 대화 내용을 Firestore `conversations` 컬렉션에 자동 저장합니다.
* **Conversations (`/api/conversations`)**: 과거에 나눈 대화 세션 목록을 최신순으로 조회합니다.

# 3. 핵심 기능 및 아키텍처 구현

## 3.1 컨텍스트 주입 (Context Injection) 메커니즘
일반적인 LLM은 개인이 보유한 주가 데이터를 알지 못합니다. StockMate는 AI가 응답을 생성하기 전, 백엔드 서비스에서 `get_data_summary()`를 호출해 Firestore의 전체 주가 통계를 먼저 계산합니다.

이후 해당 통계 지표를 OpenAI API 호출 시 `system` 역할의 프롬프트에 동적으로 삽입합니다.

이 방식을 통해 AI는 사용자의 실제 데이터 범위 내에서 정확한 수치를 인용하여 답변할 수 있습니다.

## 3.2 싱글 페이지 애플리케이션 (SPA) UI
* **Overview 탭**: NVDA 주요 지표 및 AI 인사이트 카드 대시보드
* **Data 탭**: 아코디언 형태의 상세 주가 리스트 및 모달 기반 데이터 추가/삭제 인터페이스
* **AI Chat 탭**:실시간 메시지 버블, 로딩 애니메이션, 컨텍스트 기반 챗봇 인터페이스
* **History 탭**: 타임스탬프와 메시지 카운트가 표시되는 과거 대화 세션 아코디언 뷰

## 📚 기술 개념 및 구현 원리

이 프로젝트를 통해 학습한 핵심 개념과 StockMate에서의 활용 방식을
정리했습니다.

### 1. 시계열 데이터 분석 및 요약 정보 생성

**시계열 데이터(Time Series Data)** 는 시간 순서에 따라 기록된
데이터입니다. StockMate에서는 날짜별 NVDA 주가 데이터를 사용합니다.

주가 데이터는 날짜와 종가(`date`, `value`) 등을 포함하며, Firestore에
저장된 데이터를 분석해 AI가 활용할 수 있는 요약 정보를 생성합니다.

**데이터 처리 흐름**

1.  Firestore의 `data` 컬렉션에서 주가 데이터를 조회합니다.
2.  날짜를 기준으로 데이터를 정렬합니다.
3.  종가 데이터를 이용해 데이터 개수, 평균, 최고가, 최저가 등을
    계산합니다.
4.  날짜별 종가 변화를 비교해 최근 추세를 분석합니다.
5.  계산한 요약 정보를 화면에 표시하고 AI의 시스템 프롬프트에
    전달합니다.

예를 들어 1,254개의 주가 데이터가 있다면, 모든 데이터를 매번 AI에
전달하는 대신 전체 기간과 데이터 개수, 평균·최대·최소 가격, 최근 추세
등을 요약해 전달할 수 있습니다.

단, 평균·최대·최소만으로는 최근 추세를 정확히 알 수 없습니다. 추세를
판단하려면 최근 데이터와 이전 데이터를 비교하는 등의 별도 계산이
필요합니다.

**왜 요약 정보를 만드는가?**

-   사용자가 전체 데이터를 직접 살펴보지 않아도 주요 정보를 파악할 수
    있습니다.
-   AI가 질문에 답할 때 참고할 구체적인 수치를 제공합니다.
-   전체 데이터를 매번 전달하는 것보다 프롬프트의 길이를 줄일 수
    있습니다.

### 2. FastAPI의 라우터와 서비스 분리

FastAPI는 Python으로 API 서버를 구축할 수 있는 프레임워크입니다.
StockMate에서는 기능별로 코드를 분리해 관리합니다.

  구성 요소     역할
  ------------- --------------------------------------------------------
  `main.py`     FastAPI 앱 초기화, CORS 설정, 라우터 등록
  `routers/`    API 엔드포인트와 요청·응답 처리
  `services/`   데이터 조회·분석, AI 호출, 대화 저장 등 실제 기능 수행
  `firebase/`   Firestore 연결 및 인증
  `schemas/`    요청·응답 데이터 구조와 검증 규칙 정의

예를 들어 사용자가 주가 데이터 조회를 요청하면 다음과 같이 처리됩니다.

`사용자 요청 → routers/data.py → services/data_service.py → Firestore → 응답 반환`

AI 채팅도 비슷한 흐름으로 처리됩니다.

`사용자 질문 → routers/chat.py → services/openai_service.py → 요약 정보 조회 → GPT API 호출 → 대화 저장 → 응답 반환`

**왜 분리하는가?**

라우터에 모든 코드를 작성하면 API 처리, 데이터베이스 접근, AI 호출
코드가 섞여 수정과 테스트가 어려워집니다. 역할을 분리하면 특정 기능을
수정할 때 관련 파일을 중심으로 작업할 수 있고, 오류가 발생한 위치도
파악하기 쉬워집니다.

### 3. Pydantic을 활용한 요청 데이터 검증

Pydantic은 Python 데이터의 구조와 타입을 검증하는 라이브러리입니다.
FastAPI와 함께 사용하면 API로 들어오는 요청 데이터가 정해진 형식에
맞는지 확인할 수 있습니다.

예를 들어 StockMate의 채팅 API는 다음과 같은 요청 모델을 사용할 수
있습니다.

``` python
from pydantic import BaseModel

class ChatRequest(BaseModel):
    message: str
```

이 모델은 `message`가 문자열이어야 한다는 조건을 정의합니다. FastAPI는
요청 본문을 이 모델에 맞게 검증하고, 필수 필드가 없거나 타입이 맞지
않으면 일반적으로 `422 Unprocessable Entity` 응답을 반환합니다.

주가 데이터도 다음과 같은 구조로 검증할 수 있습니다.

``` python
from datetime import date
from pydantic import BaseModel

class DataCreate(BaseModel):
    date: date
    value: float
    memo: str = ""
```

-   `date`: 날짜 형식의 데이터인지 확인합니다.
-   `value`: 숫자형 값인지 확인합니다.
-   `memo`: 메모를 문자열로 받으며, 입력하지 않으면 빈 문자열을
    사용합니다.

**왜 검증하는가?**

잘못된 데이터가 데이터베이스에 저장되는 것을 줄이고, API가 예상한 형식의
데이터만 처리하도록 하기 위해서입니다. 다만 타입 검증만으로 모든 오류가
방지되는 것은 아닙니다. 주가가 음수이면 안 된다는 조건이나 메모 길이
제한 등은 추가 검증 규칙으로 설정할 수 있습니다.

### 4. Firestore와 CRUD

Firestore는 데이터를 컬렉션과 문서 단위로 저장하는 NoSQL
데이터베이스입니다.

StockMate에서는 다음 두 컬렉션을 사용합니다.

-   `data`: 날짜별 주가 데이터
-   `conversations`: AI 채팅 대화 기록

**CRUD**는 데이터를 다루는 네 가지 기본 작업을 의미합니다.

  작업            HTTP 메서드   StockMate API
  --------------- ------------- ------------------
  Create (생성)   POST          `/api/data`
  Read (조회)     GET           `/api/data`
  Update (수정)   PUT           `/api/data/{id}`
  Delete (삭제)   DELETE        `/api/data/{id}`

예를 들어 사용자가 특정 날짜의 주가 데이터를 삭제하면 프론트엔드가 해당
문서의 ID를 API로 전달합니다. 백엔드는 Firestore에서 해당 문서를
삭제하고, 프론트엔드는 삭제 결과를 반영해 목록을 갱신합니다.

대화 기록도 `conversations` 컬렉션에 저장하고 조회하거나 삭제할 수
있습니다. 이때 각 문서의 고유 ID를 사용하면 특정 대화를 구분해 관리할 수
있습니다.

**왜 Firestore를 사용하는가?**

서버를 직접 구축하지 않고도 데이터를 저장하고 조회할 수 있으며, 문서
단위로 주가 데이터와 대화 기록을 관리할 수 있기 때문입니다.

### 5. 컨텍스트 주입: 데이터 요약을 시스템 프롬프트에 넣기

일반적인 AI 모델은 별도로 전달하지 않은 사용자의 데이터베이스 내용을 알
수 없습니다. 따라서 StockMate는 데이터 요약 정보를 GPT API 요청에 함께
전달합니다. 이를 **컨텍스트 주입(Context Injection)** 이라고 합니다.

**처리 과정**

1.  사용자가 "최근 NVDA 주가 추세가 어때?"라고 질문합니다.
2.  백엔드가 Firestore에서 주가 데이터를 조회합니다.
3.  데이터 요약 정보를 계산하거나 요약 API에서 가져옵니다.
4.  요약 정보를 시스템 프롬프트에 포함합니다.
5.  사용자 질문과 함께 GPT API에 전달합니다.
6.  GPT는 제공받은 요약 정보를 근거로 답변합니다.
7.  질문과 답변을 대화 기록에 저장합니다.

시스템 프롬프트의 예시는 다음과 같습니다.

``` text
당신은 주가 데이터를 분석하는 AI 비서입니다.

[사용자 데이터 요약]
- 데이터 기간: 2024-07 ~ 2026-08
- 데이터 개수: 1,254개
- 평균 종가: [계산된 평균]
- 최고 종가: [계산된 최고가]
- 최저 종가: [계산된 최저가]
- 최근 추세: [계산된 추세]

위 데이터를 근거로 사용자의 질문에 답변하세요.
제공된 데이터로 확인할 수 없는 내용은 추측하지 말고,
필요한 데이터가 없다고 알려주세요.
```

위 수치는 프롬프트 구조를 설명하기 위한 예시이며, 실제 값은
데이터베이스에서 계산한 결과를 사용해야 합니다.

**왜 시스템 프롬프트에 주입하는가?**

사용자 질문만 전달하면 AI가 일반적인 주식 지식에 의존하거나 실제
데이터와 다른 내용을 답할 수 있습니다. 데이터 요약을 함께 제공하면
답변을 해당 서비스의 데이터에 맞게 구성할 수 있습니다.

다만 요약에 포함되지 않은 개별 날짜의 가격까지 AI가 정확히 알 수 있는
것은 아닙니다. 특정 날짜나 특정 기간의 정확한 값을 묻는 경우에는 해당
데이터를 추가로 조회해 전달하는 방식이 필요합니다. 또한 컨텍스트 주입은
AI가 항상 정확하게 답한다는 보장은 아니므로 계산된 결과와 답변을
검증해야 합니다.

### 6. CORS, 환경변수, API 키 관리

배포된 프론트엔드와 백엔드는 서로 다른 도메인에서 실행될 수 있습니다.
StockMate에서는 Vercel에 배포한 프론트엔드가 Render의 FastAPI 서버에
요청을 보내므로 CORS와 환경변수 설정이 중요합니다.

#### CORS

CORS(Cross-Origin Resource Sharing)는 브라우저가 서로 다른 출처의 서버에
요청할 때 적용하는 보안 정책입니다.

예를 들어 프론트엔드가 `https://내서비스.vercel.app`에 있고 백엔드가
`https://내서비스.onrender.com`에 있다면 서로 다른 출처입니다.
백엔드에서 허용할 프론트엔드 출처를 설정해야 브라우저가 해당 응답을
정상적으로 사용할 수 있습니다.

개발 중에는 로컬 주소를 허용할 수 있지만, 배포할 때는 실제 프론트엔드
도메인을 허용 목록에 포함하는 것이 좋습니다.

#### 환경변수

환경변수는 API 키, 인증 정보, 서버 주소처럼 실행 환경에 따라 달라지는
값을 코드와 분리해 관리하는 방법입니다.

  -----------------------------------------------------------------------
  환경변수                            용도
  ----------------------------------- -----------------------------------
  `OPENAI_API_KEY`                    GPT API 인증

  `FIREBASE_SERVICE_ACCOUNT_JSON`     Firebase 서비스 계정 인증 정보 또는
                                      프로젝트에서 정한 인증 경로

  `ALLOWED_ORIGINS`                   백엔드에서 허용할 출처 목록

  `API_BASE_URL`                      프론트엔드가 요청할 백엔드 주소
  -----------------------------------------------------------------------

로컬 개발 환경과 배포 환경은 주소와 인증 정보가 다를 수 있으므로 각각
올바르게 설정해야 합니다.

#### API 키와 서비스 계정 키 관리

API 키와 Firebase 서비스 계정 키는 다른 사람이 사용하면 과금이나 데이터
접근 문제가 발생할 수 있는 민감한 정보입니다.

-   비밀키를 소스 코드에 직접 작성하지 않습니다.
-   GitHub 저장소에 `.env`나 Firebase 인증 JSON을 올리지 않습니다.
-   `.gitignore`를 통해 비밀 파일이 커밋되지 않도록 합니다.
-   Render 등 백엔드 배포 환경의 환경변수 설정에 인증 정보를 등록합니다.
-   프론트엔드에 비밀키를 포함하지 않습니다. 브라우저에 전달되는 값은
    사용자가 확인할 수 있기 때문입니다.

**핵심은 코드와 비밀 정보를 분리하고, 각 실행 환경에서 필요한 인증
정보를 안전하게 제공하는 것입니다.**

### 7. 전체 시스템 흐름 정리

StockMate의 전체 구조를 한 번에 정리하면 다음과 같습니다.

``` text
[사용자]
   │
   ▼
[Vercel 프론트엔드]
HTML / CSS / JavaScript
   │
   │ HTTP 요청
   ▼
[Render 백엔드]
FastAPI
   │
   ├── routers/ : 요청 처리
   │
   ├── services/ : 데이터 분석 및 AI 호출
   │       │
   │       ├── Firestore : 주가 데이터와 대화 기록
   │       │
   │       └── GPT API : 데이터 요약을 참고한 답변 생성
   │
   ▼
[프론트엔드에 응답 반환]
   │
   ▼
[사용자 화면 갱신]
```

이 구조의 핵심은 데이터베이스에 저장된 사용자의 데이터를 백엔드에서
분석하고, 그 결과를 AI에 전달해 일반적인 답변이 아닌 데이터 기반의
맞춤형 답변을 제공한다는 점입니다.
